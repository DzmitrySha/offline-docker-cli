# Политика безопасности

## Модель угроз

`offdock` разделяет работу между двумя типами машин:

- CI-раннер или машина разработчика **с сетью** заполняет offline-cache (`cache`);
- **офлайн-машина** загружает и собирает образы из этого кэша (`cache load`, `build`, `up`, `scan`).

Граница доверия — целевой репозиторий и переносимая папка `offline-cache/`. Всё, что попало в кэш, позже исполняется или собирается на офлайн-машине.

## Что защищено и как

- Токены реестров читаются **только из env-переменных** (`PROGET_API_KEY`, `NEXUS_AUTH`). User-level `sources.json` и проектный `.offline-docker.json` хранят только **имя** env-переменной (`auth_env`), никогда значение (`configure.py`, `resolve.py`).
- Auth для Nexus: `user:pass` передаётся как Basic, любое другое значение — как Bearer (`nexus_client.py`).
- Trivy-скан работает из кэшированной БД; для сканирования сеть не нужна.

## Целостность кэша

- `cache check` проверяет наличие артефактов; подписи и контрольные суммы он **не** проверяет.
- Образы тянутся **по тегу** и сохраняются через `docker save` (`download_images.py`). Для строгой проверки пинните digest образов в `docker_images`.
- Trivy DB стареет; `db_max_age_days` только предупреждает и никогда не блокирует сборку или скан (`trivy_scan.py`).

## Обязательные меры

- Используйте только доверенные целевые репозитории — их конфиг определяет, что скачивается и какие хуки выполняются.
- Предпочитайте HTTPS для ProGet/Nexus. По HTTP pip получает `--trusted-host`, а npm — `strict-ssl false`, что снижает проверку TLS.
- Используйте короткоживущие токены реестров и ротируйте их.
- Обновляйте Trivy DB на машине с сетью перед переносом бандла.
- Пинните digest образов в `docker_images`, когда важны воспроизводимость и целостность.

## Остаточные риски

- `hooks.after_cache` выполняет win/sh/script-хуки из целевого репозитория с правами текущего пользователя — произвольное исполнение кода по замыслу.
- Кэш не подписан: скомпрометированный upstream или реестр может отдать вредоносные артефакты.
- Скан покрывает только Docker-образы; wheels, npm-пакеты и debs `offdock` не сканирует.

## Реакция на инцидент

1. Остановите затронутый пайплайн и не собирайте из подозрительного кэша.
2. Отзовите и смените `PROGET_API_KEY` / `NEXUS_AUTH`.
3. Удалите и заново заполните `offline-cache/` из доверенного источника.
4. Проверьте образы по digest.
5. Просмотрите скрипты `hooks.after_cache` и историю целевого репозитория.
